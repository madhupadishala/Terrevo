# Engineer 1 scoped threat model — 2026-10-11

Scope: authenticated HTTP → tenant/domain service → server-privileged RPC → persisted field/admin/audit records. Assets: role grants, customer/employee records, device location evidence, operation identities, platform administration and audit integrity. This is an engineering analysis of implemented controls and unresolved evidence, not security acceptance.

## Observability and operating response

Existing API boundary assigns a bounded `x-request-id`, no-store responses and security headers. Existing immutable audit design retains actor/tenant/record/operation/time state; platform/unplanned decision assertions were executed. Structured redacted operational logs, error-rate dashboards and measured latency/concurrency targets have not been qualified. Do not log bearer tokens, server keys, raw sensitive source documents or precise GPS in operational diagnostics.

On a tenant/role violation, stop the affected release and preserve redacted request IDs and restricted audit references for investigation. On retry conflicts, preserve the operation identity and investigate differing payloads; do not generate a replacement UUID automatically to conceal a conflict. On a failed write, reread authoritative state through the same authorized tenant context before claiming success. On recovery failure, retain the safe test dump and failure evidence inside the isolated CI runtime; do not restore it into a hosted project.

Security review remains HOLD until live Auth/API/device qualification, helper review, concurrent/load evidence and authorized acceptance are complete. Production was not changed.
